# Library i18n hook (`MM_TRANSLATE`, `MM_LANGUAGE`, `mmT`, `liveMessages`)

Introduced with AB#6163 (Refinery Studio i18n, slice S1). Concept:
`main/wave3-concepts/studio-i18n-concept.md` §2.1, §6.

The libraries stay free of any translation framework (no ngx-translate peer dependency). They
write **English defaults** and ask the host app through optional tokens. An app that provides none
of them sees exactly the English texts it saw before.

## Tokens

| Token | Type | Default when not provided |
|---|---|---|
| `MM_TRANSLATE` | `(key, params?) => string \| undefined` | none — library defaults are used |
| `MM_LANGUAGE` | `Signal<string>` | constant `'en'` |
| `MM_TRANSLATE_DEFAULTS` | multi, `MmTranslationTable` | none |

The host returns `undefined` (or the key itself) for a key it does not know; the library default
then applies. A host lookup that throws counts as "not translated".

Host wiring with ngx-translate (Refinery Studio, `src/app/i18n/i18n.providers.ts`):

```ts
{ provide: MM_LANGUAGE, useFactory: () => inject(StudioLanguageService).lang },
{ provide: MM_TRANSLATE, useFactory: () => {
    const translate = inject(TranslateService);
    return (key: string, params?: MmTranslateParams) => {
      const value = translate.instant(key, params) as string;
      return value === key ? undefined : value;
    };
} },
```

## Library side

Keys: `MM.<LIB>.<AREA>.<camelCaseLeaf>` (concept D4), e.g. `MM.SHARED_UI.LIST_VIEW.refresh`.
Parameters use the ngx-translate syntax `{{ name }}`.

Each library that ships texts keeps `projects/meshmakers/<lib>/i18n/en.json` and `de.json`
(packaged as an asset, `ng-package.json` → `assets`). The host's translation loader merges them
under its own file (host wins). The English file is also imported as a TS constant and registered
as the default table:

```ts
import EN from '../../i18n/en.json';
provideMmTranslateDefaults(EN);          // in provideX() or a component's providers
```

Templates:

```html
{{ 'MM.SHARED_UI.LIST_VIEW.refresh' | mmT }}
{{ 'MM.SHARED_UI.LIST_VIEW.count' | mmT : { count: total() } }}
{{ 'MM.SHARED_UI.LIST_VIEW.refresh' | mmT : null : 'Refresh' }}   <!-- explicit fallback -->
```

`mmT` is impure but cached; it reads `MM_LANGUAGE`, so OnPush templates re-render on a language
switch. TS code uses `injectMmT(defaults?)` — the returned function also reads the language signal,
so `computed(() => t('MM.X.y'))` follows a switch.

Resolution order: host → `defaults` argument → `MM_TRANSLATE_DEFAULTS` tables → explicit fallback →
the key itself.

`shared-ui/i18n/en.json` + `de.json` are skeletons in S1 (namespace `MM.SHARED_UI` only); texts move
in with the later slices (S2+).

## Existing `*_MESSAGES` tokens: `liveMessages` / `messagesFromTranslate`

The existing message tokens (`SHELL_MESSAGES`, `COMMAND_PALETTE_MESSAGES`, `ASSISTANT_MESSAGES`,
`MM_ROW_ACTIONS_MESSAGES`, …) stay unchanged. Hosts fill them with a key map:

```ts
const SHELL_KEYS = { search: 'SHELL.MESSAGES.SEARCH' } as const
  satisfies Partial<Record<keyof ShellMessages, string>>;
{ provide: SHELL_MESSAGES, useFactory: () => {
    const translate = inject(TranslateService);
    return liveMessages(SHELL_KEYS, (k) => translate.instant(k) as string);
} }
```

`liveMessages` returns an object of getters over the current translation (for tokens injected once);
`messagesFromTranslate` returns a snapshot (for a `messages` input re-computed on a switch). Members
without a translation are left out / `undefined`, so the library default stays.

## Check

`npm run i18n:check` (part of `npm run lint` and the CI lint step) verifies en/de key parity,
placeholder consistency and the `MM.<LIB>.` namespace of every `projects/meshmakers/*/i18n/`.
