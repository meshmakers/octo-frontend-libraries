# OctoBot: `mm-octobot` and `mm-empty-state` (AB#3444)

The meshmakers OctoBot is a small pixel-art mascot (mint, 8-frame animated WebP) used in a few
deliberate places of the product UI. This page covers the component, the assets and the
placement rules.

## `mm-octobot`

```html
<mm-octobot animation="idle" size="md" />                         <!-- decorative -->
<mm-octobot animation="thinking" size="sm" label="Thinking" />    <!-- role="img" + aria-label -->
<mm-octobot animation="wave" size="md" playOnce />                <!-- one loop, then the still frame -->
```

| Input | Values | Default | Notes |
|-------|--------|---------|-------|
| `animation` | `idle`, `blink`, `look`, `swim`, `thinking`, `wave` | `idle` | |
| `size` | `sm` (60 px), `md` (120 px), `lg` (240 px) | `md` | Fixed `width`/`height`, no layout shift |
| `label` | string | – | Set → `role="img"` + `aria-label`; empty → `alt=""` + `aria-hidden="true"` |
| `still` | boolean | `false` | Show the still frame (first frame, PNG) |
| `playOnce` | boolean | `false` | Play one loop (`OCTOBOT_LOOP_MS`), then rest on the still frame |

The `<img>` uses `loading="lazy"`, `decoding="async"` and `image-rendering: pixelated`.

**Reduced motion:** while `prefers-reduced-motion: reduce` matches (followed live via
`matchMedia`), the still frame is shown. `OCTOBOT_FORCE_STILL` (token, default `false`) forces
stills app wide, e.g. for a user setting "Reduce animations".

## Assets

The images ship as library assets — nothing lands in the JS bundle:

```
node_modules/@meshmakers/shared-ui/assets/octobot/{sm,md,lg}/octo_<animation>.webp        (0.3–1.1 KB each)
node_modules/@meshmakers/shared-ui/assets/octobot/{sm,md,lg}/octo_<animation>_still.png   (0.25–0.4 KB each)
```

A host app copies them with an `angular.json` assets entry:

```json
{ "glob": "**/*.{webp,png}", "input": "node_modules/@meshmakers/shared-ui/assets/octobot", "output": "/assets/octobot" }
```

The component resolves URLs against `OCTOBOT_ASSET_BASE_URL` (default `assets/octobot/`, relative
to the document base). Provide another value when the files are served elsewhere:

```typescript
providers: [{ provide: OCTOBOT_ASSET_BASE_URL, useValue: 'https://cdn.example.com/octobot/' }]
```

Source: Marketing › Logo Animations › transparent (sm/md/lg WebP only; no GIFs, no xl). The still
frames are generated by `scripts/octobot/generate-octobot-stills.py` (see the script header).

## `mm-empty-state`

The shared empty / no-results / error block of a page or list — once per page, never per row:

```html
<mm-empty-state heading="No data flows yet" text="Create your first data flow to start processing data." />
<mm-empty-state variant="no-results" heading="No blueprints match the current filter" />
<mm-empty-state variant="error" heading="The MeshBoards could not be loaded." showRetry (retry)="load()" />
```

| Variant | Figure | Notes |
|---------|--------|-------|
| `empty` | OctoBot `idle` | The list or page has no records yet |
| `no-results` | OctoBot `look` | A search or filter matches nothing |
| `error` | none | `role="alert"`, optional "Try again" (`showRetry`, `retryLabel`, `(retry)`) |

`mm-list-view` renders it for you: pass `[emptyState]="{ title, text }"` and the list shows the
`empty` variant while it has no records and the `no-results` variant (texts from
`ListViewMessages.noResultsTitle` / `noResultsText`, or `filteredTitle` / `filteredText`) while a
search, row filter or `hasExternalFilters` is active. Nothing is shown while the list loads.
`[emptyTemplate]` replaces the block entirely (context: `filtered`).

## Placement rules

Approved placements (PO, 2026-10-08):

| Place | Animation |
|-------|-----------|
| Empty list / page (once per page) | `idle` |
| Search or filter without results | `look` |
| App start / page loading (after 400 ms; tiles and tables keep skeletons) | `swim` |
| Assistant: empty chat (once) | `wave` (`playOnce`) |
| Assistant: reply streaming | `thinking`, next to "Thinking…"; afterwards a still frame |
| 404, "beta feature turned off", no permission, old links | `look` |
| Onboarding, once per user | `wave` (`playOnce`) |

Never:

- inside repeated elements — list rows, table cells, cockpit tiles, cards of a grid, buttons
  (restless, hurts readability and accessibility). This is the **host's responsibility**: the
  component cannot know where it is rendered;
- in toasts (short and frequent; a figure distracts);
- on errors (keep them sober; a still frame is the most that is acceptable);
- more than one animated OctoBot per view.

Where the figure carries meaning (e.g. `thinking`), text next to it says the same, so the figure
itself can stay decorative.
